## Test quality and specific risks

- `tests/RustSelectionParity.ps1` manufactures `KEY_6` etc. rather than generating them from physical CIM records. It validly tests **function-to-function synthetic selection** but does not verify stable identity derivation, spoofed JSON, replug, cross-device disk-number reuse, driver behavior, or destructive target binding. This is a coverage limitation, **not** proof of an exploitable production defect.
- `tests/RustHardwareIdentityParity.ps1` compares the fingerprint helper against the current PowerShell function with synthetic serial/model/PNP; it does not prove that either source reads genuine USB hardware correctly.
- `tests/RustManifestParity.ps1` checks successful synthetic file/digest equality. It does not enumerate all permission failures, Windows reparse behavior, name collisions, source changes while hashing, interruptions, or physical boot semantics.
- `VALIDATION.txt` and `docs/SOURCE-REVIEW.md` contain historical Windows runs, for example `38745234537` at source `fdd5be8c1760454c82252e5ccf562e65a54e7806`; those observations are NOT current HEAD pass reports. No tests were executed for this audit. No 100-run, three-clean-cycle, fuzz, mutation, release-install or physical-device claim is made.
